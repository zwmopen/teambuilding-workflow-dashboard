# 架构

## 小猫通知边界

- `public/assistant-notification-policy.js` 只负责纯通知策略；`public/app.js` 负责队列、去重、页面来源与设置持久化；`desktop/main.js` 只负责原生悬浮窗生命周期和屏幕鼠标方向。
- 原生状态必须区分 `catVisible` 与 `bubbleVisible`。业务页面只能通过 `sourceView` 声明通知归属，不能直接让某个业务提醒永久占据全局小猫。

## 0.15.0 渐进式模块化边界

- 架构升级采用 strangler/渐进迁移：`server.js`、`app.js` 和 `styles.css` 继续作为兼容入口，新服务先以独立文件接入，测试和实机通过后再移除旧内联实现。
- 后端路由已经按备份、转化、分发、GPT 扩展、聚光、生产、设置和微信草稿 8 个业务域进入 `server/routes/`；`server.js` 保留依赖装配、共享安全边界和兼容调度。
- 前端纯规则与可注入服务使用 UMD 小模块，既可在浏览器以全局对象加载，也可在 Node 测试中直接 `require`。模块不得直接复制账号、队列或运行数据，只通过显式依赖读写唯一状态。
- 第一项服务 `gpt-runtime-recovery.js` 负责暂停队列的稳定就绪确认；工作台渲染入口提供状态快照和动作回调。两次网页状态检查都必须等待完成，期间状态变化会取消恢复。
- 兼容红线：不更改 localStorage 键、服务端运行数据格式、Electron 持久分区、素材/成品目录和 GPT 网页执行协议；每抽一个模块必须先红后绿、全量回归、暂停状态实机重启复验。

## 0.13.0 工作台调度与扩展执行

- 工作台是本地事实层：扫描素材/模板目录、计算组合、维护账号额度、持久化任务、校验成品、归档素材和备份设置。
- 浏览器扩展是网页执行层：只在真实 ChatGPT 页面内完成附件上传、发送、回复稳定检测、图片与文案提取和下载。自动模式与网页消息旁的手动下载按钮复用同一底层能力。
- 模板初始化与素材生产是两类任务。每个已选模板对应一个新会话；初始化成功后，该会话串行处理所有已选素材。未选择模板时不会新建会话。
- 每套作品的状态机为：排队、初始化模板、上传附件、等待计划、自动确认、生成图片、请求文案、下载、打包校验、素材归档、完成。失败记录阶段和检查点，重试从失败阶段继续。
- 每账号账本按滚动三小时事件计算上传与生成消耗。调度器只接纳能完整放入剩余额度的任务，超额任务进入等待；网页限流、验证和登录过期会覆盖本地估算并暂停。
- 素材归档只有一个入口：服务端确认批次图片、TXT 和成品目录全部存在后，才允许在配置素材根目录内部移动帖子文件夹；同名目标永不覆盖。
- 原生 `WebContentsView` 在工作台弹窗或其他功能页打开时隐藏，避免压住 DOM 弹窗。账号初始化使用共享 Promise，防止快速切换造成重复网页实例。
- GPT 登录分区不进入普通 JSON 或云端备份。本机恢复点使用“写入待办 → 重启 → 网页分区尚未打开时复制/恢复 → 再启动”的顺序，避免热复制被锁定的 SQLite/Cookie 文件。

## 0.12.2 GPT 网页自动生产链路

- Electron 主进程使用 `WebContentsView` 承载真实 `https://chatgpt.com/`。每个账号使用 `persist:teambuilding-gpt-production-<id>` 独立持久分区，Cookie、登录状态、浏览历史和页面导航互不共享。
- 渲染页负责素材/模板树、勾选状态、账号切换与串行队列。一个母版映射多个素材时，每个素材形成一个独立任务；上一组真实完成或按设置跳过后才进入下一组。
- 典型附件为母版前两张图（封面与通用内页）加当前素材文件夹中的图片、TXT/Markdown；提示词合并长期母版规则、文件角色和当次补充要求。
- 现有浏览器扩展在嵌入态不渲染重复生产舱，但负责原生附件上传、计划检测、自动确认、新图片检测、文案检测、精确批次下载和结果回传；本地文件仅允许从工作台授权接口读取。
- 主进程与网页扩展通过一次性任务编号和 DOM 事件桥接。成功、失败、取消都必须回传；未登录、无附件入口或超时会在工作台明确失败，不能伪装为已送入。
- 每组下载生成唯一批次号，文件名携带批次、序号和总数。服务端只允许该批次进入工作包脚本，并在返回成功前复核图片张数、TXT 和输出目录，避免下载目录旧文件串包。
- 生产间隔由页面设置给出最短和最长秒数，渲染页在两组之间随机等待。该等待只调节正常队列节奏；平台验证、登录失效和限流由扩展识别并暂停。
- 工作台不读取、导出或注入 Google/OpenAI 凭据。Cookie 只存在 Electron 用户数据分区，Git、诊断与业务日志均不记录。
- 打包应用优先加载 `integrations/gpt-production-extension` 内置运行快照；源码开发优先加载独立扩展仓库。同步脚本只复制 manifest、后台脚本、内容脚本、样式和网页助手运行文件，不复制测试或浏览器数据。

## 0.12.1 校准优先生产状态机

- `/api/production/run` 固定以 `runScope=calibration` 启动，只允许计划中第一套作品的第一张 P1 进入生图函数。
- 首图成功后任务进入 `calibration-ready`，结果、输出目录与请求审计均持久化；`/resume` 只有在该状态下才把范围切换为 `full`。
- 首图失败时任务保持 `runScope=calibration`，再次恢复仍只允许重试 P1；中断或失败不能绕过校准直接生成整套。
- 完整续跑按“作品 + 页码”识别已落盘结果，跳过 P1，再串行生成剩余页面和每套文案。
- 正式付费生成显式传入 `attempts=1`。下载供应商返回图片 URL 仍可沿用普通网络重试，但不会重复提交付费生成 POST。
- OpenAI 兼容与 MiniMax 适配层返回统一的 `requestMeta`：请求数、尝试数、响应状态、耗时、供应商 request id、参考图数与 usage。密钥、完整请求体和参考图数据不会写入记录。

## 0.11.6 增量备份与短期任务表面

- `webdav-backup.js` 提供目录逐层建立和文件流式 PUT；服务端不把大文件一次性读入内存。
- WebDAV 网络请求使用 `undici` 的环境代理调度器，便携应用会沿用本机 `HTTP_PROXY / HTTPS_PROXY / ALL_PROXY`；代理只解决网络可达性，401 仍按鉴权失败处理。
- `cloud-large-backup-manifest.json` 只保存在运行数据目录，记录相对路径、大小、修改时间、已备份时间和月度上传量。软链接不扫描；原文件不移动、不删除。
- 自动备份定时器每 15 分钟检查是否到期，实际周期来自页面设置（每天 24 小时、每周 168 小时或自定义）。小数据成功后再启动方案增量任务；同一时间只允许一个大文件任务。
- 当前方案备份根与流量转化方案索引共用企微微盘公司目录；两个模块各自持久化路径，工作台不复制 730 个来源文件或 729 份方案索引。
- 分发/普通传送任务的内存表只保留进行中与最近 3 分钟结果；DELETE 接口只允许清除非运行任务。长期历史仍由真实操作日志和传送记录承担。
- 流量转化资源代理在改写 `/api/*` 时保留嵌入页自身 fetch 包装器的原始判断，避免 `/conversion-integrated/conversion-integrated/api/*` 双前缀。
- `/api/workbench-assistant/interpret` 只让文本模型返回预定义意图和参数；前端再次映射到允许动作。模型输出不能成为命令行、路径或任意接口调用，确定性命令在本地直接解析，减少耗时与模型消耗。

## 0.11.5-dev 同源脚本代理与界面约束

- `/conversion-integrated/` 不仅改写入口 HTML 中的静态资源和接口地址，也会改写外部 JavaScript 内以单引号、双引号或模板字符串书写的绝对 `/api/*` 请求，避免嵌入模块误访问工作台根接口。
- 工作台页头的帮助和设置操作采用固定尺寸 SVG 图标；通用按钮容器不得覆盖其宽高、圆角或 `flex-basis`。
- 设置页使用 12 栏网格时，每张一级设置卡必须声明跨度；小于 1180 像素时所有一级卡片占满整行。
- 生产三栏在桌面、中等窗口和窄窗口分别采用三栏、收缩三栏和单栏布局；所有可变文本容器必须允许换行并设置 `min-width: 0`。

## 手机准话助手安全边界

- 完整工作台仍只面向电脑本机；开发模式可监听局域网，但远程请求默认全部拒绝。
- 手机首次通过带随机令牌的 `/mobile-conversion` 入口进入，验证后写入 HttpOnly、SameSite=Strict Cookie，再跳转到轻量页面。
- 局域网仅开放 `/mobile-conversion/app` 与 `/mobile-conversion/api/search`；素材库、模板库、设置、生产和分发接口不向手机开放。
- 手机页不复制完整知识库，不读取手机聊天记录，只把用户输入转发给电脑内现有智能匹配接口并展示必要结果。
- 访问令牌存于运行时私密目录，不属于项目配置，也不得写入日志之外的可发布资产。

## 0.11.4 计划确认状态机

- 前端以 `activeProductionPlan` 作为两阶段状态：为空时主按钮调用计划接口；存在时同一主按钮调用确认生产接口。
- `renderProductionPlan()` 只渲染计划内容，并驱动固定操作坞切换为“返回调整 / 确认并开始生成”；不再在计划 HTML 内重复创建临时按钮。
- `invalidateProductionPlan()` 统一清理计划、编辑按钮和主按钮状态，避免模板、素材或参数已经变化却继续确认旧计划。
- 真实图片仍由当前选定图片平台执行，文案由独立文本模型执行；当前本地 GPT 通道逐页串行生产，模板与素材参考在每页请求中保持同一配方，但尚未实现供应商级会话缓存。

## 0.9.4 连接状态与可审计分发

- Electron 主窗口直接加载本地工作台，不再启用 `webviewTag`、ChatGPT guest 会话、网页脚本注入或多账号内嵌登录；外部网页仍由本地白名单接口交给系统浏览器。
- `device-presence.json` 仅在运行数据目录保存最近发现的设备摘要；本轮未回包的设备最多保留 10 分钟并标为“最近在线”，实际发送仍由共享 Skill 重新发现和连接。
- `app-settings.json` 可保存生图 API 类型、HTTPS 地址和模型名；密钥只读取 `TEAMBUILDING_IMAGE_API_KEY`，不写入设置文件或前端响应。当前版本只完成可接入界面与安全配置层，不包含未经验证的供应商调用。
- 局域网设备发现记录被标准化为 `transport=wifi`，前台从真实发现状态生成连接标签；USB、远程保留独立状态位，未获得底层事实时不得显示为在线。
- `transfer-progress.js` 从底层完成 JSON 中提取实际 `transport`，完成任务可显示本次传输使用的协议。
- 发送闭环顺序保持为：原子 claim → 设备接收确认 → 追加 `device-usage-log.csv`（含传输协议）→ 完成 claim → 原作品集移动到公众号目录。历史记录即使遇到入口误建，也会阻止再次进入手机待发送库存。

## 0.9.1 分类按需加载与素材身份层

- 素材文件夹身份由文件系统目录身份派生为 SHA-256；同卷改名或移动后保持不变，内容相同的两个目录也不会共用身份。
- `material-hash-cache.json` 缓存路径对应的目录身份和文件夹哈希。
- `防重复账本/material-metadata-ledger.json` 以文件夹身份哈希为键保存人工母标签与使用次数。
- 图片、TXT、Markdown 的聚合内容指纹仍由使用台账保存，只用于内容防重，不再充当文件夹身份。
- `/api/materials` 只为用户展开的分类计算并返回元数据，避免打开工作台时全库同步哈希。
- `materialCategoryIndex()` 只读取素材根目录的直接子目录；`materialCategoryCache` 按分类路径独立缓存递归结果，顶层签名变化时不会复用已不存在的分类。
- `/api/dashboard` 只装载状态中当前分类，`/api/materials` 无分类参数时只返回轻量索引；两条入口不再先构造完整素材库再隐藏未展开内容。

```text
项目推进（素材/模板/成品/生产记录/发布空间）
              ↓ 只读为主
工具开发/teambuilding-workflow-dashboard/src
              ↕
运行数据/江湖有旅人/图文生产控制台
              ↑
AI/skills/技能包/技能
  ├─ teambuilding-xhs-workflow（生产方法）
  └─ device-folder-transfer（分发执行与安全规则）

独立浏览器扩展 teambuilding-gpt-production-extension
              ↓ 仅本机接口
   授权目录 / 文件流 / 生产去重只读状态
```

`server.js` 提供仅监听本机回环地址的 HTTP API、静态页面、设备自动刷新、可恢复传输任务进度/取消、扩展只读协作接口和分发 Skill 白名单调用；`lib/transfer-progress.js` 把底层输出转换为用户可见阶段和百分比；`lib/dedup-ledger.js` 区分生产历史与分发历史；`lib/distribution-data.js` 从 Junction、台账和 CSV 日志计算作品集状态；`public/` 是工作流控制台；`desktop/` 承载本地界面；`mcp/` 保留聚光数据调用入口。

生产防重与分发防重是两套独立事实：生产历史库按整组图片 SHA-256 确定重复，并用 64 位 dHash 做近似预警；分发防重继续使用 claim、使用日志和入口状态。两类数据都不复制进公开源码。

手机发送、接收确认和 Junction 安全删除不在工作台中重写，而是调用 `device-folder-transfer`。工作台负责任务选择、输入校验、系统内最终确认、进度、取消、结果呈现和状态刷新；普通文件传输与作品包补笔记使用同一设备发现、任务表现和传输真源。软链接兼容层属于执行内核，不在前台显示。

作品包防重采用三层互锁：发送前在 `.distribution-claims/` 原子创建独占 JSON 占用；接收成功后写入 `device-usage-log.csv`；最后删除对应活动 Junction。任何一层显示已占用/已使用，随机与指定分发都拒绝再次发送。

平台资格分为两个使用组：小红书与抖音是同一手机组，候选必须同时存在两个有效同源入口，使用一次后整组退出；公众号是独立组，其入口与手机组互不消耗。
# 0.9.6 本地生产任务

- `lib/production-recipes.js`：把长期会话规则变为模板配方、页面计划、逐页生图提示和文案提示。
- `POST /api/production/plan`：只读素材、模板和事实文件，生成有时效的待确认计划。
- `POST /api/production/run`：只接受已存在的计划 ID，创建后台任务，不在 HTTP 请求中阻塞整套生成。
- `GET /api/production/jobs/:id`：返回阶段、进度、待审目录和已生成文件，不返回密钥。
- `lib/image-generation.js`：统一调用兼容生图接口和文本模型。
- 运行数据：任务状态写入 `production-jobs`；作品写入 `API生产待审`。正式成品库仍需人工质检批准后进入。
