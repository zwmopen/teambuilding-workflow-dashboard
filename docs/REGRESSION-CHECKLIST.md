# 团建工作台问题回归库

这不是待办便签，而是每次开发和交付都必须执行的质量门禁。用户已经报告过的问题一旦进入本库，后续版本不得复发。

## 使用规则

1. 开发前先查本次改动会影响哪些编号。
2. 修复必须写清：复现条件、最早根因、代码修复、自动测试、桌面实测。
3. 没有自动测试的项目必须说明原因，并保留可重复的人工步骤。
4. “当时看起来正常”不算通过；必须经过触发原问题的完整操作序列。
5. 登录态、任务队列、用户文件等高风险状态，验证前先确认不会被测试破坏。
6. 相关回归项没有全部打勾，不允许更新正式使用入口或宣布完成。

## 交付门禁

- [ ] 相关自动测试全部通过。
- [ ] 真机按原始复现步骤再次操作。
- [ ] 检查修复没有清缓存、删除登录态或重置用户设置。
- [ ] 检查运行中的生产任务没有因界面切换而中断。
- [ ] 记录最终版本、提交、测试数量和仍存在的限制。

### UI-GPT-001｜最小化或退到后台后 GPT 白屏

- 状态：已修复，永久回归。
- 原始现象：GPT 页面和任务实际仍存在，但最小化、托盘隐藏后恢复工作台时，右侧只显示白色占位层。
- 复现条件：进入“内容生产（GPT）”并显示原生 GPT 视图 → 最小化或关闭到托盘 → 恢复工作台。
- 根因：最小化时主动隐藏 `WebContentsView`；Windows 恢复最小化窗口触发 `restore`，旧代码只监听 `show`，因此没有重新显示原生视图。
- 修复标准：同时监听 `show` 与 `restore`；恢复后重新挂载原生绘制层但不 reload ChatGPT；保持原会话 URL、登录态和生产阶段；容器重新具有 `is-native-visible`。
- 自动测试：`public/workbench-ui.test.js` 中“restoring a minimized workbench reattaches the live GPT surface without reloading it”。
- 桌面验收：真实最小化后恢复；确认 GPT 可见、扩展 ready、任务仍 running 且阶段未倒退。
- 最近证据：2026-08-01 实机通过；生产任务保持“等待图片”；提交 `caa6610`。

### TEMPLATE-001｜链接模板与文件夹模板双模式

- 状态：已确认产品规则，待当前生产批次结束后实现。
- 链接模式：模板由“名称＋ChatGPT 会话链接＋可选绑定浏览器”构成。开始任务时直接在指定浏览器访问该链接，确认会话可用后仅上传素材；不重复上传母版图片。
- 链接模板真源：用户所选模板库根目录下的 `链接模板.txt`。一行一个模板，默认使用 Tab 分隔：`模板名称<Tab>https://chatgpt.com/c/...<Tab>浏览器档案ID（可选）`。同时兼容 `模板名称 | 链接` 和首个空白后为链接的简写；空行及 `#` 开头的注释忽略。
- 编辑规则：界面允许手动粘贴名称和链接；新增、修改、删除必须原子写回同一个 TXT。用户在记事本中修改 TXT 后，工作台自动扫描并刷新，不要求点击“读取”。名称或 URL 重复时提示合并／更名，不静默覆盖。
- 文件夹模式：模板由真实本地文件夹构成，包含母版图片及提示词／TXT。开始任务时创建新聊天，先上传模板并初始化母版环境，再逐个上传素材。
- 共同规则：模板区域顶部明确切换两种模式；两种模板可以分别多选；作品数仍按“素材数 × 模板数”计算；同一批任务冻结模板类型和来源；链接模板打不开或账号无权访问时只暂停该模板任务，不串到其他账号或模板。
- 数据安全：只保存模板名称、合法的 `https://chatgpt.com/` 会话 URL、本地路径和浏览器档案 ID；拒绝非 ChatGPT 域名及非会话链接；不保存 Cookie、Token 或账号密码。写回前先生成同目录临时文件并原子替换，避免断电导致整份列表损坏。
- 自动测试：URL 白名单、模板模式切换、笛卡尔积队列、浏览器绑定、链接失效降级和文件夹初始化测试。
- 桌面验收：1 个链接模板＋1 个文件夹模板 × 2 个复制素材，分别生成 4 个独立任务；确认链接模式没有上传母版、文件夹模式真实上传母版、两个账号不串号。

### WORKFLOW-001｜生产模式必须提供可见、可编辑的阶段流程

- 模式口径：`单窗口自动（有提示词）` 保留完整模板/迁移提示词；`单窗口自动-随机` 复用当前已沉淀会话，只上传素材、等待计划、发送 `1`、等待图片，再发送可编辑的文案请求词。

- 状态：当前仅支持编辑确认词和文案请求词；完整流程编辑器待当前生产批次结束后实现。
- 入口：右键“手动模式／单窗口自动／多窗口自动”可打开该模式的流程编辑器；右上角生产设置提供同一入口。两个入口编辑同一份配置。
- 阶段结构：每一步明确显示“阶段名称、触发条件、执行动作、发送文字、等待上限、失败处理、是否启用”。允许新增、复制、停用和在满足依赖时调整顺序。
- 默认单窗口流程：
  1. 任务开始 → 上传当前素材与首轮要求；
  2. 检测到计划稳定完成 → 等待 1–5 秒 → 发送可编辑确认词，默认 `1`；
  3. 检测到本轮图片完成 → 下载本轮图片，同时发送可编辑文案请求词，默认 `给我一份小红书文案`；
  4. 检测到文案完成 → 复制并写入 TXT → 校验图片和文案 → 查重打包；
  5. 打包成功 → 记录成品路径 → 按开关归档素材 → 进入下一套。
- 动作类型：上传素材、等待计划、发送文字、等待图片、下载本轮、请求文案、等待文案、复制 TXT、查重打包、归档、结束／跳过。
- 安全依赖：不得把“发送 1”放到计划完成前，不得在图片和文案校验前打包；界面拖动到无效顺序时直接提示原因，不保存假流程。
- 版本与恢复：流程配置写入工作台 `app-settings.json` 并包含版本号；支持“恢复当前模式默认流程”和导出／导入；不得只保存在浏览器 localStorage。
- 任务冻结：点击开始生产时，把当时的流程保存为本批快照；运行期间修改只作用于下一批，不得改变当前任务。
- 可解释性：生产记录逐阶段写入实际触发条件、发送内容、开始／结束时间和结果，使用户能追溯“这句提示词从哪里来”。
- 自动测试：流程解析、依赖校验、模式隔离、运行快照、默认恢复、设置备份和失败跳过测试。
- 桌面验收：右键三个模式分别编辑；重启后配置仍在；运行中修改不影响当前批；日志能够显示每一步实际发送的内容。

### FLOW-GPT-004：单窗口继续生产没有重新注入素材

- 现象：单窗口任务在本地额度提醒或桥接前暂停后，点击“继续生成”只进入恢复分支，GPT 页面没有重新出现附件。
- 根因：队列旧任务被统一写入 `retryFromStage`，扩展把它当成已经上传过的网页阶段任务，跳过了文件选择；同时单窗口错误复用了多窗口的本地额度硬闸。
- 修复标准：单窗口本地额度只做提示；桥接前暂停的任务必须从素材树补齐附件并传 `forceUpload=true`；已送达 GPT 的任务才允许按阶段恢复。
- 自动测试：工作台 `160/160`；扩展 `15/15`，包含 `forceUpload` 和重试分支断言。
- 桌面验收：选择一个素材，触发本地额度提醒后暂停，再点击继续；应再次看到真实附件上传，不能只显示“恢复阶段”。
- 数据安全边界：不删除或重建 GPT/Google 登录分区，不清理 Chromium 缓存，不移动素材原文件。
- 状态：已修复，待真实桌面复现确认。

### FLOW-GPT-005：低图数触顶后继续喂素材或只提醒不自动探测

- 现象：本轮只生成 1–3 张后仍继续发送后续素材；或虽停止，但 3 小时后只提醒、不自动用下一条素材试跑。
- 根因：低图数原先只作为任务错误处理；额度提醒计时器没有连接生产队列，且残缺任务仍停留在当前索引。
- 修复标准：1–3 张立即停止；残缺任务失败并跳过；不下载、不文案、不打包、不归档；按第一次进入生图阶段 + 默认 3 小时自动试跑下一条；重启后恢复探测定时器。
- 自动测试：`public/workbench-ui.test.js` 校验低图数识别、索引跳过、自动探测、周期重置和定时器恢复入口。
- 桌面验收：下一次真实额度周期观察一轮 1–3 张触顶；确认小猫提示、队列停止、到点自动试跑下一条，且未清理登录状态。
- 数据安全边界：不删除 Chromium/GPT 分区，不重建浏览器档案，不移动未成功素材。
- 状态：代码与自动测试已完成；等待下一次真实额度周期桌面验收。

### FLOW-GPT-006：全天自动跨重启与工作时段恢复

- 现象：一批结束后不再选下一批；合盖、断网或重启后即使探测时间已到也不会继续；深夜仍可能启动新作品。

- 自动测试：校验工作时段控件、跨午夜判断、持久运行键、联网/页面恢复监听和启动恢复入口；完整回归 `165/165`。

- 数据安全边界：不得清理 GPT/Google 登录分区、浏览器缓存、素材原目录或成品历史。
- 状态：代码、热更新和自动测试已完成；真实 3 小时跨周期行为需在后续生产中持续观察。
