# 团建工作台问题回归库

这不是待办便签，而是每次开发和交付都必须执行的质量门禁。用户已经报告过的问题一旦进入本库，后续版本不得复发。

## 使用规则

1. 开发前先查本次改动会影响哪些编号。
2. 修复必须写清：复现条件、最早根因、代码修复、自动测试、桌面实测。
3. 没有自动测试的项目必须说明原因，并保留可重复的人工步骤。
4. “当时看起来正常”不算通过；必须经过触发原问题的完整操作序列。
5. 登录态、任务队列、用户文件等高风险状态，验证前先确认不会被测试破坏。
6. 相关回归项没有全部打勾，不允许更新正式使用入口或宣布完成。

## 交付门禁

- [ ] 相关自动测试全部通过。
- [ ] 真机按原始复现步骤再次操作。
- [ ] 检查修复没有清缓存、删除登录态或重置用户设置。
- [ ] 检查运行中的生产任务没有因界面切换而中断。
- [ ] 记录最终版本、提交、测试数量和仍存在的限制。

### MAINT-001｜独立扩展与工作台内嵌副本版本漂移

- 现象：独立扩展代码已更新，但工作台内嵌 `manifest.json` 仍停留在旧版本，导致开发测试通过而实际加载旧执行器。
- 根因：同步时只复制了脚本文件，没有把清单版本纳入一致性门禁。
- 修复标准：独立扩展与内嵌副本的 `manifest.json`、核心脚本和 vendor 脚本必须逐项哈希一致；每次扩展版本更新同步提升内嵌清单。
- 自动测试：扩展清单版本断言；发布前执行源文件/内嵌文件哈希对比。
- 状态：代码已修复，待本轮完整测试。

### FLOW-GPT-009｜会话状态不明确时提前注入下一帖

- 现象：当前对话还处于等待计划、等待图片或等待文案阶段，工作台又上传了下一帖；脚本/Python 降级输出还可能被误当成品。
- 根因：旧桥接主要依赖局部按钮和计时，没有形成可审计的当前对话状态快照。
- 修复标准：网页执行器必须返回当前会话标签、最新助手正文、图片数、计划/确认/文案/限额/脚本信号和 `canInjectNext`；只有完成、明确失败跳过或安全空闲才允许领取下一帖。
- 自动测试：扩展状态快照、脚本降级停止、当前会话无提示词复用测试。
- 桌面验收：真实计划完成后 1–5 秒只发一次 `1`；等待图片期间不得出现下一帖附件；脚本/Python 输出立即暂停。
- 状态：代码与自动测试已补，待真实桌面复验。

### UI-GPT-001｜最小化或退到后台后 GPT 白屏

- 状态：已修复，永久回归。

- 自动测试：`public/workbench-ui.test.js` 中“restoring a minimized workbench reattaches the live GPT surface without reloading it”。
- 桌面验收：真实最小化后恢复；确认 GPT 可见、扩展 ready、任务仍 running 且阶段未倒退。

### FLOW-GPT-004｜文案未完成却提前下载或生成半成品

- 自动测试：扩展“automatic packaging waits for validated copy text before final image download”；工作台生产记录路径和缺文案状态测试。
- 桌面验收：让图片回复先完成、文案未完成时确认不下载/不打包；文案完成后确认先落盘暂存 TXT，再下载图片，最终 TXT、图片和成品文件夹同时落盘；历史成品缺项时显示“打开成品文件夹（待核对）”。

### WORKFLOW-001｜生产模式必须提供可见、可编辑的阶段流程

- 模式口径：`单账号·手选自动（有提示词）` 保留完整模板/迁移提示词；`单账号·手选自动` 复用当前已沉淀会话，只上传素材、等待计划、发送 `1`、等待图片，再发送可编辑的文案请求词；`单账号单模板·永不停歇` 按同一账号窗口严格一帖一帖循环。

- 状态：当前仅支持编辑确认词和文案请求词；完整流程编辑器待当前生产批次结束后实现。
- 入口：右键“手动模式／单账号单模板·永不停歇／多账号窗口自动”可打开该模式的流程编辑器；右上角生产设置提供同一入口。两个入口编辑同一份配置。
- 阶段结构：每一步明确显示“阶段名称、触发条件、执行动作、发送文字、等待上限、失败处理、是否启用”。允许新增、复制、停用和在满足依赖时调整顺序。
- 默认单窗口流程：
  1. 任务开始 → 上传当前素材与首轮要求；
  2. 检测到计划稳定完成 → 等待 1–5 秒 → 发送可编辑确认词，默认 `1`；
  3. 检测到本轮图片完成 → 下载本轮图片，同时发送可编辑文案请求词，默认 `给我一份小红书文案`；
  4. 检测到文案完成 → 复制并写入 TXT → 校验图片和文案 → 查重打包；
  5. 打包成功 → 记录成品路径 → 按开关归档素材 → 进入下一套。
- 动作类型：上传素材、等待计划、发送文字、等待图片、下载本轮、请求文案、等待文案、复制 TXT、查重打包、归档、结束／跳过。
- 安全依赖：不得把“发送 1”放到计划完成前，不得在图片和文案校验前打包；界面拖动到无效顺序时直接提示原因，不保存假流程。
- 版本与恢复：流程配置写入工作台 `app-settings.json` 并包含版本号；支持“恢复当前模式默认流程”和导出／导入；不得只保存在浏览器 localStorage。
- 任务冻结：点击开始生产时，把当时的流程保存为本批快照；运行期间修改只作用于下一批，不得改变当前任务。
- 可解释性：生产记录逐阶段写入实际触发条件、发送内容、开始／结束时间和结果，使用户能追溯“这句提示词从哪里来”。
- 自动测试：流程解析、依赖校验、模式隔离、运行快照、默认恢复、设置备份和失败跳过测试。
- 桌面验收：右键三个模式分别编辑；重启后配置仍在；运行中修改不影响当前批；日志能够显示每一步实际发送的内容。

### PACKAGE-001：手动打包与自动打包结果不一致

- 现象：自动生产可打包，但用户手动点击“下载并打包”提示“打包程序已结束，但没有找到成品文件夹”。
- 根因：两个入口分别组装请求；手动入口未固定传递当前下载/成品目录，且 PowerShell 中文 stdout 可能被错误解码为另一个合法字符串。
- 修复标准：两种入口共用 `packageDownloadedReply`；服务端按批次号从 UTF-8 `GPT作品记录.json` 恢复权威成品路径；文案或图片不完整时二者都不允许报成功。
- 自动测试：扩展共用函数与禁止 `window.alert`；工作台中文路径恢复、工作包重复与在线目录测试。
- 桌面验收：在同一助手回复先执行“下载本组”，再执行“下载并打包”，确认成品目录存在且不会弹旧版假失败。
- 状态：代码和自动测试已完成，待 0.14.7 开发版桌面复测。

### FLOW-GPT-004：单窗口继续生产没有重新注入素材
