本轮针对“计划出来后误注入下一帖”“明明有多张图却检测成 1 张”“脚本/拼图产物被当作正常生图”的判定漏洞完成复核和修复。当前只做检测与安全边界修复，未恢复暂停队列、未继续消耗真实生图额度。

### 已定位的真实根因

- ChatGPT 的助手正文位于 `[data-message-author-role="assistant"]`，生成图片和脚本附件常位于同一个 `conversation-turn-*` 外层的兄弟节点；旧代码只扫正文节点，会漏掉真实图片和下载按钮。
- 同一张图片会被渲染为大图、缩略图、懒加载图，并带不同签名 URL；旧代码按完整 URL 去重，会把一张图算成多张。
- 生成图缩略图常只有 48×48，旧的通用图片尺寸过滤会把它们丢掉，真实 6 张可能被误判为 1 张。
- 旧风险规则对正文中任意“重试”“Python”字样都过于敏感，计划说明里的普通文字可能被当成限额/脚本失败。
- 计划判定只看“文本够长且出现 P1/迁移计划”，没有强制等待“回复 1/暂不出图/回复完成”证据，存在回复尚未稳定就进入下一阶段的窗口。

### 已实现的检测边界

- 新增 `replyScopes()`：计划、图片、脚本附件、复制回复按钮统一绑定当前 `conversation-turn`，不再跨历史回复取证。
- ChatGPT `backend-api/estuary/content?id=file_*` 按稳定 `id` 去重，不受签名、缩略图和全尺寸 URL 变化影响。
- 生成图专用选择器允许 48×48 缩略图计数；普通兜底 DOM 仍保留 160px 尺寸过滤，避免头像/图标混入。
- 当前回复存在原生图片时，图片列表优先使用原生图片；Python/沙盒附件只作为风险证据，不能替换真实图片数量。
- Python 风险改为“Python 脚本/代码/文件/输出”、代码解释器、运行代码、分析图片尺寸等强信号；“重试/额度”改为明确限额句、失败句或当前回复 1–3 张且存在重试按钮才触发。
- 计划必须满足可解析页数，并且同时具备原生复制回复完成动作或“暂不出图/等待回复 1/请回复 1”等完成标记；不满足时返回 `PLAN_NOT_COMPLETE`，暂停当前帖子，不发送 `1`，不上传下一帖。
