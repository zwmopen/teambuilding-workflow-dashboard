# 团建工作台项目手册与持续检查清单

> 这份手册是开发、热更新、真实生产测试和交付前 review 的共同入口。新增需求先登记，再实现，再验证；没有通过的项目不能标记为完成。

## 当前工作原则

- 开发版优先热更新；不删除 Chromium/GPT/Google 登录分区、缓存、账号窗口、用户配置或生产记录。
- 一次只让一个账号窗口处理一个帖子。当前帖子未完成、跳过或安全暂停前，不允许向该窗口注入下一帖。
- 真实网页状态优先于本地额度估算。遇到验证码、验证、限流、脚本输出或低图数异常，暂停当前帖子，记录原因，等待下一次探测。
- 手动和自动只区分触发者，下载、TXT、查重、打包、归档必须走同一条本地工作包链路。
- 失败不伪造完成：缺 TXT、图片不足、下载不完整或成品目录不存在时，不归档素材、不显示成功。

## 三个生产模式

1. **手动模式**：选择一个帖子，上传到当前账号窗口；后续发送、复制、下载或打包由用户操作。
2. **单账号单模板·永不停歇**：绑定当前账号窗口和当前会话模板；一个帖子完成后才继续下一个，按使用次数从低到高选择素材。
3. **多账号单模板·永不停歇**：每个账号窗口有独立队列、会话、额度组和检查点；每个窗口仍然一次只处理一个帖子，互不串号。

每个模式都支持右键“修改模式设置、重命名、删除配置（确认）”。模式配置至少包括：

- 继续当前会话 / 注入模板提示词；
- 自动确认文字；
- 文案请求词；
- 阶段超时、最低图片数、自动复制/下载/打包/归档；
- 工作时间、定时启动、并行账号窗口数和账号绑定。

## GPT 状态机检查

当前会话状态必须能落到以下之一：

`ready → uploading → waiting-plan → plan-ready → waiting-images → images-ready → waiting-copy → copy-ready → packaging → archived → completed`

必须检查：

- 侧边栏/当前会话是否包含“模板”或已绑定模板；不符合时不得盲目注入。
- 计划正文稳定后 1–5 秒内只发送一次确认文字；计划未完成不得发送。
- 生成图绑定当前回复；脚本/Python/压缩包输出、重试或限额信号立即停止当前帖子。
- 图片和 TXT 都完成后才能打包；生成 1–3 张时按低图数异常处理，不请求文案、不打包、不归档。
- 已完成或已失败的检查点恢复时，不重复上传、确认、文案请求或归档。
- 输入框残留的自动草稿可清理；用户无关草稿仍是硬边界，不覆盖。

## 统一工作包验收

- “下载全部”只下载当前回复图片，不创建成品。
- “下载全部并打包”先保存/校验本轮文案 TXT，再下载图片、查重、写入成品库。
- 成品目录必须真实存在，并包含图片、非空 TXT、`GPT作品记录.json` 和批次元数据。
- 只有完整成功或明确查重跳过后，才把源素材移动到“已使用一次/两次/三次”。
- 生产记录必须提供实际成品路径、图片/TXT 数量、阶段耗时、错误阶段和“打开成品文件夹”。

## 小猫助手与层级

- 小猫、状态气泡、日志和对话框属于同一通知层，必须覆盖 GPT 网页；GPT 网页不能遮挡或把它压到下层。
- 气泡只展示最新状态和日志；点击小猫打开对话，点击气泡查看当前页面日志；拖动不触发点击。
- 任务运行中显示当前账号窗口、帖子、阶段、百分比和耗时；暂停后按钮必须变为“继续”。
- 状态提示必须去重，不再在 GPT 网页右上角重复弹出同一提醒。

## 每次改动后的门禁

- [ ] 复现原问题并记录 runId/taskId、账号窗口、会话 URL、阶段和本地文件状态。
- [ ] 实现修复，不改变登录分区、缓存和用户数据。
- [ ] 运行工作台自动测试，当前基线不低于 181/181。
- [ ] 运行扩展自动测试，当前基线不低于 32/32，并通过 `npm run check`。
- [ ] 运行 `git diff --check`，检查嵌入副本与扩展源文件一致。
- [ ] 做桌面开发版复验：切换账号窗口、暂停/继续、残留草稿、计划→1、出图→文案→打包。
- [ ] 检查成品目录、TXT、图片数量、归档次数和生产历史真实路径。
- [ ] 运行系统质检脚本并记录报告位置。
- [ ] 只有全部通过后才更新交接文档、CHANGELOG、版本号或正式包。

## 本轮待复验重点

- [ ] 手动 12:55 左右的下载/打包是否成功落到成品库；若只有暂存图片，记录为未完成而不是成功。
- [ ] 计划完成后当前窗口不会提前注入下一帖。
- [ ] 单账号模式使用当前会话时不重复注入模板提示词；选择“注入”时使用 V3.6 规则。
- [ ] 多账号模式每个窗口只领取一帖，额度/阶段/恢复时间独立。
- [ ] 旧生产记录中的缺 TXT/缺图片状态显示“待核对”，可打开真实目录。

## 维护结构改造路线

当前不做一次性重写，按以下顺序逐模块迁移并保持 API 兼容：

1. `public/app.js`：先拆账号窗口与额度、生产状态机、素材/模板树、全局助手、生产历史五个模块。
2. `server.js`：按目录扫描、GPT 工作包、生产记录、备份、分发拆成路由与服务层。
3. 扩展 `sidebar.js`：拆 DOM 状态识别、上传/发送、图片下载、文案提取、工作台桥接。
4. 每迁移一个模块，先保留旧导出适配层，自动测试与真实桌面复验通过后再删旧实现。

结构优化验收指标：

- 页面切换不触发 GPT reload；素材树只懒加载展开内容。
- 单一事件只注册一次监听器，定时器和 `ResizeObserver` 可追踪、可销毁。
- 状态机和 DOM 识别可独立测试，不依赖整份 9 千行脚本。
- 源扩展与内嵌副本具有自动哈希一致性检查。
